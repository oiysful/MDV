## Lessons Learned
- Always run plain `npm audit` (full tree) for the headline supply-chain claim, not `--omit=dev` — devDependencies include electron itself for an Electron app, which is part of the shipped runtime even though npm classifies it as "dev". `--omit=dev` is fine as a *secondary* signal for "what ships in the app bundle" but must never be the sole basis for a "0 vulnerabilities" claim.
- 2026-08-06: user ran `npm audit fix` themselves. Resolved: electron 42.3.0→42.8.0 (moderate GHSA-r4w5) and both undici advisory instances. NOT resolved: brace-expansion (high, GHSA-rgw5-rvv9-x895) and fast-uri (high, GHSA-7p8r-x3mc-p8w7) — confirmed upstream-blocked, not just conservative-fix-blocked: patched versions exist on npm (brace-expansion 5.0.9, fast-uri 4.x) but are nested inside electron-builder's own transitive deps (minimatch, ajv); electron-builder is already at its latest release (26.15.3) and hasn't bumped those deps yet, and `npm audit fix --force --dry-run` produced byte-identical output to the non-forced run — npm found no resolvable path at all. Only real options: wait for an electron-builder release, or add `overrides` in package.json to force the patched versions across the tree (untested against electron-builder's actual behavior — do not do this reflexively). Re-check on next `/security-audit` or whenever electron-builder is bumped.
